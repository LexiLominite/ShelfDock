# Install on a saved machine

Choose **Install on this device** in a machine's menu. **Check Machine** probes the actual SSH destination, then shows its operating system, processor, app version and user-account installation folder. A saved POSIX machine may be Linux or macOS; its saved label never substitutes for the probe. Plans expire after five minutes, are single-use and require unchanged saved connection details.

Linux supports x64 and arm64. Windows supports x64 portable releases. macOS uses the existing verified app-bundle installer and requires the current Mac build to match the destination processor. The app remains closed after installation; open it on the destination when ready.

Linux packages install under `~/Applications/<release-package-folder>`. Windows portable packages install under `%LOCALAPPDATA%\Programs\ShelfDock` or `LexBridge`. macOS uses `~/Applications`. Linux creates a user launcher under `~/.local/share/applications/<app>-<version>-<arch>.desktop`. Windows creates a shortcut in the current user Start Menu. Existing installation folders, launchers and shortcuts are refused. A failure publishing the launcher or shortcut rolls back only the newly installed app and owned artifacts. The installer writes an owned staging folder, validates the upload and moves the prepared app into place. Failure removes staging where the SSH connection permits it; a failed cleanup is reported with the staging path. Remove the newly installed app folder and its user launcher or Start Menu shortcut to roll back this fresh installation. No existing app or user settings are overwritten.

The Linux/Windows download is pinned to the sender's version, edition, operating system and architecture in the fixed release repository. SHA-256 checksums, Linux executable processor and app identity/version must match. Linux app.asar metadata is read without running the payload. Windows portable launcher headers and PE product/version resources are checked on the sender and again through FileVersionInfo at the destination. The portable launcher may be x86 while the embedded app is x64; payload architecture is pinned by the exact release asset name/checksum and must be checked by release packaging verification. The public edition uses anonymous GitHub downloads. Personal releases use GitHub CLI authentication on the sender; credentials are never copied to the destination. Only app payloads and installer scripts cross SSH. Personal builds may contain a bundled machine preset and require an explicit sharing checkbox; local credentials, clipboard, shelves and runtime settings remain local.

Cancel check closes the compatibility preview and discards any late reply. Key-based SSH probes receive an abort signal; existing saved-password and Mac probes settle before the backend releases its lock. A cancelled preview cannot create an installation plan. Cancel installation stops downloads and prevents the final remote installation from starting. Key-based SCP uploads receive the installation abort signal. Saved-password transfers use an abortable SFTP stream, closing only that SFTP channel so the SSH session can remove staging. Uploads have a ten-minute deadline. The UI shows Cancelling until cleanup settles. Cancellation is unavailable during the final atomic installation or the existing Mac bundle installation. Shutdown waits for running work and requests cancellation before the commit boundary.

## Validation limits

Automated tests use simulated SSH destinations and pinned release fixtures. They verify Linux arm64 and Windows x64 routing, plan expiry/reuse, saved-key changes, consent, cancellation, sender-only private download endpoints and wrong-hash/product rejection. Native Windows PowerShell execution and real Linux/macOS installation require release qualification on those platforms. No remote machine was changed by the fixture tests.

## Standalone public installation

[Public bootstraps](bootstrap.md) support Linux x64/arm64 through curl or wget with Python 3, and Windows x64 through PowerShell. Save and review the bootstrap, then run it without interactive prompts. It downloads a fixed-version package, checksum manifest and payload installer from the public ShelfDock release; verifies their checksums and application identity before installation; and leaves the app closed. These scripts require the corresponding assets to be published. Private LexBridge installation remains the authenticated sender-over-SSH route, with explicit preset consent and no credentials copied.

Bootstrap fixture tests are separate from native platform qualification. Native Windows downloading, execution policy, shortcut creation and updater behavior require verification on Windows before production support is claimed.
