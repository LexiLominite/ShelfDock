# LexBridge Mobile protocol v1 (shared implementation contract)

Personal Android companion 0.1.0. Desktop0.7.4 stays unchanged and running. Default bridge port18474; private runtime ~/.config/lexbridge-mobile (0700). Bridge listens0.0.0.0 but rejects any remote address outside loopback and Tailscale100.64/10. Cleartext is only acceptable inside Tailscale encrypted overlay or loopback; app rejects other HTTP endpoints and requires normal certificate validation for HTTPS. No public exposure, conversation scanning, automatic alerts, or remote commands.

Credential scopes: agentToken may POSTnotifications and GETnotification status only; ownerToken may manage devices/pairing/outbox and state; per-device token permits its state/events/inbox upload/file downloads/acks only. Persist secrets outside source; agent config {version:1,endpoint:"http://127.0.0.1:18474",token:agentToken}. Paircode >=96 random bits expires10min and consumes once. Devices revocable. Never tokens in URL query/logs. Pair input URL+code, not autoapproval.

All responses application/json unless binary or SSE. Errors {error:"safe message"}. JSON requests and ordinary JSON responses are limited to 64 KiB. Device GET /v1/state is limited to 2 MiB; owner state omits notification bodies and is limited to 8 MiB. Each device has a 1 MiB JSON UTF-8 notification quota, reserving acknowledgement growth. Only acknowledged history may be pruned; queued saturation returns 429. At most two uploads stream concurrently, separately from journal mutations; global file history is bounded to 8000 records. Global notification JSON is bounded to 4 MiB with reserved acknowledgement growth; the journal is bounded to 12 MiB before committing a mutation. Only acknowledged entries may be pruned. IDs UUID. ISO8601 UTC dates. maxFileBytes default1GiB configurable. Filenames strict basename/control/path/separator rejection; no overwrite, symlink, traversal. Stream bodies; SHA256 verify. Atomic journal/spool/receipts; never claim queued as delivered.

Routes:
- GET /v1/health no auth -> {protocolVersion:1,serverName:"LexBridge",maxFileBytes}
- POST /v1/pair {code,deviceName} -> {deviceId,token,serverName,protocolVersion:1,maxFileBytes}. only private clients, single-use code.
- GET /v1/state device/owner -> {protocolVersion:1,serverName,deviceId,files:[{id,name,size,sha256,direction:"to-phone"|"from-phone",createdAt,status:"queued"|"received"}],notifications:[{id,title,body,source,severity:"info"|"success"|"warning"|"error",createdAt,status:"queued"|"received"|"displayed"}],connection}. Device only own rows; owner also devices:[{id,name,lastSeenAt}]. Do not expose raw paths/secrets.
- GET /v1/events device -> text/event-stream. event: state; data:{"type":"state-changed"}. Send initial event, heartbeat comment every20s; refresh state on event. Bounded backpressure/disconnect revoked peers. Reconnect uses state so no reliance on event cursor.
- POST /v1/inbox?name=URLencoded-basename device; raw octet-stream (chunked allowed), optional X-Content-SHA256 for knownhash. -> {file:{id,name,size,sha256,direction:"from-phone",createdAt,status:"received"}}. Desktop/Drift-ISOtimestamp-random8 + final .dropharbor-receipt.json using existingReceived schema to appear in desktop Received. One collision-safe batch per upload. Partial files excluded; abort/error cleans owned temp. No overwrite originals.
- POST /v1/outbox?name=URLencoded-basename&deviceId=UUID owner; raw stream -> {file:{id,name,size,sha256,direction:"to-phone",createdAt,status:"queued"}}. Explicit owner desktop file CLI; durable spool.
- GET /v1/files/UUID/content device owns to-phonefile -> rawbytes Content-Length/Disposition and X-Content-SHA256. Never arbitraryfilesystempath.
- POST /v1/files/UUID/ack device {sha256} -> {status:"received"}. Must match file'sexpected hash; marks receipt whenAndroid downloaded/verified/published file. Bounded spool cleanup retention.
- POST /v1/notifications agent/owner {title,body,source,severity,deviceId?:UUID,eventId?:UUID} -> {id,status:"queued",recipientCount}. title120/body8192/source64; unknownfields reject. No link/action execution. Broadcast only paireddevices atsendtime; no recipients -> HTTP409 {error:"Pair a phone first."}; no claimed delivery. eventId idempotent under sameagent credential. Offline rowsdurable. PhoneUI Inbox/Files/Alerts/settings backgroundconnection switch with disconnect; latestalerts only once stableidpersisted. Localnotification privacy generic lockscreen publicversion.
- GET /v1/notifications/UUID agent/owner -> {id,status,recipientCount,receivedCount,displayedCount}. No invented delivery; source/fetch tokens are distinct.
- POST /v1/notifications/UUID/ack device {displayed:boolean} -> {status:"received"|"displayed"}. Android onlyafter notificationreceived/persisted, displayedtrue onlyallowednotifications; deniedpermission showsin-appalert andackreceived.

CLI bridge entry main.cjs: init, serve, pair, status, send <path> --device UUID, revoke UUID. Init generatesprivateconfig+agent.json; no secrets stdout. pair printsprivate pairing instructions to a0600file (path onlystdout), optional --show explicitly to console; server URLdefaults supplied --endpoint validatedTailscaleIP. Preserve runtimefilesnotgit. Root chooses liveendpoint and runs launchagent, agents onlysyntheticfixtures.

Android: native Java, Android 10 (API 29) or newer, target/compile 36, AGP 8.11.1, Gradle 8.13 and Java 17. Application ID com.lexilominite.lexbridge. Use ACTION_OPEN_DOCUMENT and Android share intents for multiple files. Receive into MediaStore Downloads/LexBridge; verify SHA-256 before publishing IS_PENDING rows and recover interrupted publication/ack without duplicates.

An explicitly enabled connectedDevice + remoteMessaging foreground service maintains the private connection for exchanging files with the owner's desktop and receiving explicit text alerts. It declares CHANGE_NETWORK_STATE as the connected-device prerequisite. Incoming files download through the already running connection service; never start a new dataSync foreground service from a background SSE callback. Finite user-initiated uploads/manual receive may use a separate dataSync service with timeout cancellation. Both services share a serialized transfer engine. No boot receiver, background activity launches, session scanning or automatic agent alerts. A quiet ongoing notification has Disconnect. Android 13+ notification permission is requested; denied permission still permits the in-app Alerts inbox. Credentials use Android Keystore AES-GCM and are excluded from backup. Every endpoint is validated before opening a socket: HTTP allows literal loopback/Tailscale 100.64/10; HTTPS additionally accepts .ts.net with normal certificate verification. Never follow redirects or bypass TLS verification. Release signing secrets stay outside source.
