# Independent mobile review

Reviewed bridge and Android source plus notification integrations on 2026-10-02. Scope was read-only for bridge/Android, disposable fixtures, and this report. No live phone alerts, device pairing, desktop rebuild, or host configuration changes were performed. The integration HTTP-409 classification was corrected with a regression assertion in its existing fixture suite.

## Capacity blocker resolved with explicit bounds

The original state response mismatch was reproduced with nine legal 8,192-character alerts: HTTP 200 returned **75,420 bytes**, exceeding Android's former 65,536-byte response limit. The final design gives device `/v1/state` a 2 MiB bound and owner state an 8 MiB bound, with owner alert bodies omitted. Android permits 2 MiB specifically for state while retaining 64 KiB for other JSON. The bridge enforces a 1 MiB serialized notification quota per device, reserving acknowledgement status growth; only acknowledged history is pruned. Queued saturation returns 429 without silently dropping pending alerts. File history is bounded to 500 per device and 8,000 globally. A **4 MiB global notification quota** and **12 MiB central journal limit** were subsequently added; the final **14/14 bridge tests** verify refusal rather than unbounded mutation, acknowledged-only global pruning, and restart availability.

## Findings corrected during review

- **Outbox crash durability:** bridge originally renamed an fsynced partial file to its final spool name and journaled `queued` without syncing the spool directory. The bridge agent added a spool-directory sync before state save. Source verification confirms that order. Restart tests pass, but synthetic process restart cannot prove power-loss behavior.
- **Disconnect/Forget race:** Android's event refresh could finish an outstanding JSON call after service cancellation and still persist/display an old alert. The Android agent added session checks after the blocking state fetch, before display/ack, and before subsequent persistence; these compare the active vault identity/endpoint and connection state. Source checks confirm the guards. Actual Android race execution remains unverified.
- **Unpublished MediaStore setup failure:** insertion and pending-receipt persistence originally occurred before download cleanup protection. The Android agent moved pending persistence and connection setup inside the protected `try/finally`. Source checks confirm a failed pending-receipt write reaches cleanup.
- **HTTP 409 interpretation:** the notification CLI originally treated every 409 as no recipients, but the bridge also uses 409 for reusing an event UUID with different content. The client now recognizes the bridge's specific no-recipient response; unrelated conflicts remain HTTP errors. The fixture suite checks both cases.

## Mac installer and shortcuts review

The optional installer now preflights ownership/collisions and symlinks before stopping an existing service. It stages a separate versioned bundle and copies only companion source plus the desktop receipt helper; it does not replace the running desktop application. Credentials, signing keys, and runtime data are not copied into the bundle. Private backups include a recovery manifest. Control files are written atomically. If bootstrap or later wrapper/link/shortcut publication fails, it restores the previous plist, current bundle link, wrapper, shortcuts, and installation record, and restarts the prior running service. A first-install failure removes new control files and preserves staged source/private recovery files for diagnosis. Reinstall validates an owned disabled plist, includes it in private backups/rollback, and removes it only after successfully publishing the new installation; stop-reinstall-stop remains supported. The stop action preserves data, refuses a disabled-plist collision before stopping, and is idempotent.

Shortcut file selection is returned as a JSON path array rather than line-separated text. All selected paths are validated before any send, so a newline filename cannot be interpreted as multiple unrelated paths. Ordinary files, Unicode, spaces, and quotes remain supported; unsafe names/control characters/symlinks are rejected. Full device UUID labels avoid selection collisions. Arguments use subprocess arrays; no interpolated shell evaluation or embedded credentials. Unknown shortcut actions are rejected. Bridge calls have explicit subprocess timeouts, and queued results remain accurately described as queued.

**Ten mocked installer/shortcut tests passed**: separate-bundle staging/private modes; upgrade bootstrap failure rollback; first-install bootstrap failure cleanup; failure after current-link switch; unowned wrapper and record-symlink rejection; reversible/idempotent stop and disabled-file collision preservation; JSON file paths; complete selection validation before send; stop-reinstall-stop; and failed reinstall from a stopped state restoring the disabled plist. All tests used disposable directories and mocked `launchctl`/Node initialization, without a live service or GUI invocation. The AppleScript dialog source compiled successfully with `osacompile`; no dialog was executed.

Actual macOS installation, launchd service health, desktop preservation checks, GUI execution, live credential scope, and real phone delivery remain root's runtime gates. The shared Python tools use only the standard library; the Mac dialog JSON serialization uses the system Foundation framework.
