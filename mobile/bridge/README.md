# Personal LexBridge mobile bridge

Node 22+ standard library only. No packages, desktop-profile changes, session scanning, command execution, or automatic agent hooks. Read `../PROTOCOL.md` for the Android wire contract. Runtime credentials and uploaded bytes live outside this source tree.

```sh
node mobile/bridge/main.cjs init --endpoint http://100.64.0.10:18474
node mobile/bridge/main.cjs serve
node mobile/bridge/main.cjs pair
node mobile/bridge/main.cjs status
node mobile/bridge/main.cjs send /absolute/path/report.pdf --device DEVICE_UUID
node mobile/bridge/main.cjs revoke DEVICE_UUID
node --test mobile/bridge/test.cjs
```

Substitute the host's actual Tailscale IPv4 address. `init` prints paths only. `pair` prints the path of a private 0600 JSON file containing the endpoint, code and expiry; open it locally to enter those fields on the phone. `--show` explicitly prints pairing secrets. A code contains 144 random bits, expires after ten minutes, and consumes once. Successfully consumed files are deleted. Expired instructions remain private until the owner removes them. `--runtime DIR` selects an isolated runtime; `serve --desktop DIR` selects an isolated received-files destination. Production defaults are `~/.config/lexbridge-mobile` and the OS user's `~/Desktop`.

`serve` binds port 18474 on all IPv4 interfaces but rejects connections outside loopback and Tailscale 100.64/10, including dotted IPv4-mapped IPv6 forms. Tailscale provides transport encryption between machines. Do not publish or forward the port, or place a public proxy in front of it. Host headers must contain private numeric addresses or localhost. Browser origins are rejected; this is a native HTTP API with bearer credentials and no cookie authentication or CORS. Owner credentials are accepted only over loopback; an owner CLI always calls loopback even if pairing advertises a tailnet address. Agent tokens can only create alerts and inspect their delivery status. Device tokens can only access that device's rows and transfers.

The private `agent.json` has `{version:1,endpoint,token}` for explicit stdio/Python agent integrations. `config.json` additionally has the owner token and limits. Neither `init` nor `status` prints tokens. Preserve those files outside Git. The server does not trust forwarded-client-address headers. A proxy which masks all clients as loopback defeats the source-address boundary and must not be used. Native Tailscale IP connections are intended.

Owner extensions used by the CLI are `POST /v1/pairings` with JSON `{endpoint}` returning `{pairingFile,expiresAt}`, and `POST /v1/devices/UUID/revoke` returning `{revoked:true}`. Pairing APIs return a local file path, never the code. The public `/v1/pair` route returns a newly scoped device token after checking the one-time code. Revocation removes the device credential, closes its event streams, removes its pending spool files and notification recipient records; completed user-owned Desktop files stay available.

Uploads are streamed through exclusive private staging files, limited to 1 GiB by default, and hashed while writing. Each phone's pending desktop-to-phone spool defaults to 2 GiB. Incoming phone files have a separate 2 GiB daily quota per phone, resetting at UTC midnight; the persisted daily counter survives restarts and history pruning. At most two uploads stream concurrently; per-device byte reservations prevent overlapping streams exceeding a quota. The journal queue covers publication only, so an active file transfer does not block agent alerts. Chunked uploads reserve available capacity up to the maximum file size until they finish. Limits may be configured by changing `maxFileBytes` and `quotaBytes` in private `config.json` while the service is stopped.

There are at most 32 phones, 500 file records and 500 alert rows per phone, 8000 file records globally, and 1000 alert records globally. A phone's alerts also have a 1 MiB UTF-8 JSON byte quota, including array overhead and space reserved for acknowledgement-status growth. Global notification storage has a separate 4 MiB byte quota with acknowledgement growth reserved, and the entire persisted journal is centrally bounded to 12 MiB before every write. At history or byte limits the server removes old acknowledged metadata or returns 429/409; it never silently evicts a queued transfer or alert. Global byte pruning removes only wholly acknowledged notification records. Idempotency is retained as long as that notification's bounded history record exists. Reusing an event ID with different content returns 409. No paired recipient returns 409, `Pair a phone first.` JSON requests remain limited to 64 KiB; device state responses are bounded to 2 MiB. Owner state excludes alert bodies and is bounded to 8 MiB, matching the owner CLI response limit.

An incoming phone upload becomes a distinct `Desktop/Drift-TIMESTAMP-random8` folder with a final `.dropharbor-receipt.json` encoded by the existing desktop Received validator. Directory publication happens only after bytes, hash and receipt are complete. A disconnected or hash-failed upload removes its staging directory. Startup removes only specifically named owned `.part` directories and orphaned spool files. Journal and receipt writes use flush-and-rename with directory fsync. It never changes the desktop profile or shelf. Desktop OS permissions still apply; macOS may require allowing Desktop access to the service process.

File acknowledgement requires the exact stored SHA-256. It changes queued to received and deletes the private spool bytes; future downloads return 410. Alerts remain queued until the actual device acknowledges persistence, and displayed is recorded only when the phone reports a displayed notification. Status aggregate counts preserve per-recipient distinctions. Event streams deliver an initial refresh event and a heartbeat every 20 seconds; backpressure disconnects slow readers, which recover by fetching current state. At most two streams per phone are permitted.

Use direct HTTP only on loopback or the encrypted tailnet. The service accepts HTTPS only as an advertised validated private URL; it does not terminate TLS itself. For this personal service use the direct HTTP tailnet endpoint. CLI service locking prevents simultaneous writers and can recover an exited process's lock. Do not independently edit the journal or start another backend against the same runtime.

## Isolated native Android interoperability fixture

`node mobile/bridge/interop-fixture.cjs --root /absolute/path/to/an/empty/fixture-directory` starts the real backend only on loopback port 18475, using a private runtime and simulated Desktop inside that empty directory. Omitting `--root` creates a private OS temporary directory. It refuses the real Desktop and production-runtime locations. It prints only the endpoint and paths of private pairing instructions and nonsecret `verification.json`; pair codes and credentials do not print. The pairing instructions include Android test overrides `expectedFileText` and `expectedAlertTitle`.

After the first successful pairing response finishes, it explicitly queues only `desktop-to-phone.txt` containing `LexBridge native interoperability download` followed by a newline, and one alert titled `Native interoperability check`, to that fixture device. The Android fixture uploads `phone-to-desktop.txt` containing `LexBridge native interoperability upload` followed by a newline. The backend verification result becomes complete only after an exact-hash outgoing-file acknowledgement, actual alert receipt/display acknowledgement, and validation of the incoming bytes, hash and existing desktop Received receipt. `node mobile/bridge/interop-fixture.cjs --status --root DIR` prints that nonsecret result. SIGINT/SIGTERM close the owned backend; files remain for inspection. No production recipients or source profiles are consulted.

`node --test mobile/bridge/interop-test.cjs` runs a disposable HTTP smoke test of the fixture itself. That smoke test proves fixture plumbing; real native Android interoperability additionally requires running the Android instrumentation test against a separately started fixture. Do not run fixture smoke tests simultaneously with a native test using port 18475.
